OpenAI Now Processes Indian Business Data Inside India

#OpenAI#AIIndia#DataResidency#EnterpriseAI

TL;DR

  • OpenAI has started processing API requests inside India, not only storing customer data here.
  • The feature works only with the GPT-6 Luna model for now, through the Responses and Chat Completions APIs.
  • Eligible customers must create a new API project and pick India for both storage and processing.
  • Businesses that were holding back AI work over in-country processing now have a way forward.

01.What OpenBI announced

On 12 November 2026, OpenAI introduced local processing for its API in India, allowing eligible businesses and developers to run supported AI workloads inside the country. The offering initially supports the GPT-6 Luna model, and it extends the data residency options the company already offered in India.

The detail that matters is where the answer is generated. Until now, Indian customers could keep supported content stored on servers in India, but the computation that produced a response could happen elsewhere. Under the new setup, OpenAI says it will process API requests and run the model computation within the country as well.

02.Why processing is different from storage

Data residency is often read as a question about where files sit. For a bank, a hospital chain, an insurer or a company handling government contracts, that was never the whole question. Sensitive records could be stored locally and still travel out of the country for the few seconds it took a model to read them and write an answer. Compliance teams looked at that second step and said no.

In-country processing closes that gap for the supported workload. It also sits comfortably with how Indian organisations have been reading the Digital Personal Data Protection Act, 2023, which makes them accountable for personal data they handle. Keeping both storage and computation in India removes one category of review from an AI project, and review time is often the real reason a pilot never becomes a purchase order.

The practical way to read this is to ask two separate questions of any AI vendor. Where is my data kept, and where is it worked on. Indian buyers have become fairly good at asking the first and fairly slow at asking the second, which is why so many pilots stalled at the security review stage rather than at the budget stage. A regional endpoint makes the second answer simple to give, at least for the workloads it covers.

03.How a business turns it on

The mechanism is a regional endpoint. Eligible customers create a new API project, select India for both data storage and processing, and use the India regional endpoint. The capability currently covers GPT-6 Luna input and output through the Responses and Chat Completions APIs, for direct API usage.

That last part is worth noting for teams that reach models through a third-party platform or a reseller rather than directly. Local processing is an option on OpenAI's own API, so a company routing its work through another layer should check whether that layer passes the India setting through before assuming it applies.

For a team already running on OpenAI's API, the change is administrative rather than technical. Nothing about how a request is written changes. What changes is which endpoint receives it, and that choice is made once, when the project is created, which is why OpenAI is asking customers to start a new project instead of switching an existing one.

04.What it means for Indian startups

Nitin Bawankule, who heads enterprise business for OpenAI in India, explained the reasoning plainly: some Indian businesses had not fully deployed AI for important work because they needed the information involved to be processed within the country. Local inference, he said, gives them more control over where supported workloads run and addresses a practical barrier to adoption.

For Indian software teams the practical effect is a new line in a sales conversation. A startup building a claims tool for an insurer, or a document assistant for a lender, can now tell the customer that the model reading their files runs on infrastructure inside India. That is easier to get past a security questionnaire than an explanation about global regions. The announcement also builds on OpenAI's wider India push this year, which covered infrastructure, enterprise adoption, skills development and a partnership with the Tata Group on domestic data centre capacity.

05.The limits to keep in mind

The scope is narrow for now. One model, GPT-6 Luna, through two APIs, for direct customers only. OpenAI has not published the full eligibility criteria, and it has not said when other models will get the same treatment. Prices and performance in the India region were not detailed either, so teams should benchmark before moving production traffic.

Local processing also does not change what the model does or how it is governed. Company policies on what data may be sent to an AI tool still apply, and a regional endpoint does not by itself make a use case compliant with sector rules. Treat the announcement as one blocked door opening, not as the end of the compliance work. The thing to watch over the next few months is coverage: whether more models arrive on the India endpoint, and whether the India region gets new releases at the same time as the rest of the world or lags behind.

There is also a staffing angle that gets less attention. Enterprises adopting AI under a data residency condition usually need someone in-house who can explain the setup to an auditor, and that skill is thin in the market. The people who can write the policy note and the code are the ones Indian employers are competing for right now.

Frequently asked questions

Does OpenAI now store and process Indian data only in India?
For eligible customers using the India regional endpoint with the GPT-6 Luna model, both storage and the computation behind responses happen in the country. Other models and other setups are not covered yet.

Can a small business use local inference in India?
The feature is for API customers who qualify. A small firm that builds on the API directly can apply by creating a new project and choosing India for storage and processing, but eligibility terms are not fully public.

Is local processing enough to meet Indian data rules?
No. It removes one concern about where data travels, but your obligations under the Digital Personal Data Protection Act and any sector rules still apply to what you send and why.
